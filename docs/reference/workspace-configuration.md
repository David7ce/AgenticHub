# Workspace configuration

The hub derives its checkout path from its source files. No fixed drive, username
or clone-folder name is required. The supported deployment is Windows; see
[Getting started](../getting-started.md) for the Windows/WSL client boundary.

| Location | Purpose |
|---|---|
| `consent.json` | Local grants; copied from `consent.example.json`, ignored by Git |
| `acp/agents.json` | Local executables and agent defaults; copied from the example, ignored by Git |
| `<clone>/results/` | Answers, inflight records, locks and raw benchmark output |
| `<parent>/projects/logs/` | Default audit log, task/search databases and evidence |
| `<parent>/projects/working/` | Optional personal handoff, journal and roadmap |
| `<parent>/.mcp.json`, `<parent>/opencode.json` | Optional client configurations generated by `init --workspace` |

The sibling `projects/` folder is a state location, not a shipped repository or
required repository-inventory application. Keep its contents private. The hub
never needs the author's other repositories or knowledge vault.

| Environment variable | Overrides |
|---|---|
| `AGENT_HUB_STATE` | State directory, normally `<parent>/projects` |
| `AGENT_HUB_RESULTS` | ACP result directory, normally `<clone>/results` |
| `AGENT_HUB_LOG` | Audit log path |
| `AGENT_HUB_REGISTRY` | Agent registry path for dispatch |
| `AGENT_HUB_CONSENT` | Consent file for dispatch |
| `AGENT_HUB_INFLIGHT` | Inflight directory |
| `AGENT_HUB_LOCKS` | Write-lock directory |
| `AGENT_HUB_TASKS_DB` | Task database path |

These overrides are component-specific; they do not relocate every local file as
one unit. In particular, doctor reads the checkout's local consent and registry,
and some control-room views use their own default paths. Inspect the relevant
component before creating multiple installations or a fully isolated test setup.

`hub init --workspace` keeps existing files. After moving or renaming the clone,
review existing client configurations and update their server paths. Claude's
workspace path is relative to the parent; OpenCode's generated path is absolute.

The command modules live under `hubctl/commands/`, one module per subcommand.
`hubctl/hubctl.mjs` dispatches; `hubctl/common.mjs` holds shared paths and helpers.
